## 2026-11-05 (итерация 6.1)

### Double-buffering CPU↔GPU (overlap) — настоящий рычаг скорости
- Добавлен `overlap` в `trainLayeredVAE` (и в pipeline/CLI арг 9): один command
  buffer «в полёте». Шаг N отправляется, а ждём шаг N-1 (уже считается на GPU);
  кодирование шага N+1 перекрывается со счётом шага N. `GpuSession` получила
  неблокирующий `commit()` → `CommittedStep` (wait() возвращает время GPU и
  возвращает стейджинг в пул на вызывающем потоке — BufferPool не потокобезопасен;
  completed-handler лишь сигналит семафор).
- **Корректность**: математика не меняется (те же сцены/seed'ы/порядок очереди
  command buffer'ов). `testLayeredOverlap` доказывает: синхронный vs overlap
  дают БИТ-В-БИТ одинаковые firstLoss/lastLoss/PSNR/SSIM. 621 проверка, 0 падений.
- **Замер на реальном видео** (16 сцен, 80×56, C=32, 6000 шагов каждая):
  синхронно 61.7 с → overlap 43.8 с = **×1.41**. C резко PSNR 27.18 дБ /
  SSIM 0.9912 в обоих — т.е. за то же время теперь уходит в ~1.4 раза больше
  шагов к полу 30 дБ.
- **Термо**: скважность 90.0% в обоих режимах, аварий 0, GPU стартовала 81 °C
  и остыла к 76–77 °C (под потолком 85). Безопасно для длинных прогонов.
- Чекпоинт и превью не менялись (пайплайн тот же). Готово к прогону 50–100k шагов
  с overlap для попытки пройти пол 30 дБ / 0.90.

### Прогон 50k с overlap (00:20–00:27) — плато подтвердилось
- Запуск: `pipeline <видео> 16 50000 96 72 2.0 1 1` (overlap вкл).
- Итог: loss 0.27841 → 0.01000; PSNR **27.73 дБ**; SSIM 0.9923; пол 30 дБ НЕ
