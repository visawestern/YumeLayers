# YumeLayers

**YumeLayers** — программа, которая учится восстанавливать движение в видео.

Суть простая: вы даёте ей **два кадра** — начало и конец отрезка — а она **достраивает все кадры между ними** так, чтобы получилась плавная последовательность, похожая на настоящее видео.

---

## 1. Идея

Видео — это просто много картинок (кадров) подряд. Если у нас есть первый и последний кадр отрезка, можно попробовать «додумать» всё, что между ними.

Самое простое решение — смешать картинки. Но когда кадры сильно отличаются (персонаж ушёл в сторону, камера двинулась), смешивание даёт смазанное месиво: лицо «тает», фон плывёт.

Чтобы результат выглядел как настоящее видео, программа должна **понять, как именно движется изображение**:

- что было на первом кадре,
- что стало на последнем,
- куда сместились детали, что появилось и что исчезло.

Этому мы и учим нейросеть — на реальных парах кадров из того же видео. После обучения она умеет предсказывать промежуточные кадры так, что движение выглядит естественным.

Всё работает **полностью на вашем компьютере**: видео никуда не отправляется, интернет не нужен. Программа сама научается на вашем материале — чем больше кадров вы ей покажете, тем точнее результат.

Программа написана на языке Swift, без сторонних библиотек искусственного интеллекта — все вычисления написаны вручную и используют видеокарту (GPU) для скорости.

## 3. Что нужно для запуска

- **macOS** и компьютер с видеокартой, поддерживающей Metal (практически любой Mac от 2016 года; лучше с отдельной видеокартой).
- **Инструменты разработчика Xcode** (команда `xcode-select --install`).
- Свободное место на диске: сама программа занимает немного, но обучение создаёт файлы моделей (сотни мегабайт).

Сборка — одна команда:

```bash
cd /Users/apple/projects/YumeLayers
scripts/build-app.sh
```

После этого в корне проекта появится приложение **YumeLayers.app** — его можно просто открыть двойным щелчком.

(Более быстрый способ для разработчиков: `swift build -c release` и запуск `open .build/release/YumeLayersUI`.)

## 4. Как пользоваться — простой путь

1. **Откройте приложение.**
2. **Выберите видео.** Кнопка «Обзор…» → укажите файл `.mp4`.
3. **Извлеките кадры.** Кнопка «Извлечь кадры» — программа вытащит кадры из видео (по умолчанию первые 256). Кадры держатся в памяти; на диск записываются только те, что вы сами назначите опорными.
4. **Назначьте начальный кадр (A).** Листайте кадры и нажмите **«Кадр → A»** (кнопка есть и прямо под видео).
5. **Назначьте конечный кадр (B).** Нажмите **«Кадр → B»**.
   Под видео сразу видно два маленьких превью — какой кадр назначен начальным, а какой конечным.
6. **Обучите движение.** Кнопка «Обучить движение» — займёт несколько минут, прогресс виден в журнале. Это самое важное: сеть учится именно на вашем отрезке.
7. **Создайте видео.** Кнопка «Интерполяция» — результат появится в папке `outputs/`.

Всю эту последовательность можно выполнить и запросами (см. раздел 6) — это удобно, когда нужно повторить процесс много раз или управлять программой из другого скрипта.

## 5. Немного о том, как это устроено (для любопытных)

Программа состоит из двух обучаемых частей:

1. **Сжиматель кадров (VAE).** Каждый кадр превращается в «скрытое представление» — компактную таблицу чисел, в которой сохранён главный смысл картинки (как архивирование, но не побайтовое, а «по смыслу»).
2. **Сеть движения.** Она смотрит на скрытые представления начального и конечного кадров и предсказывает, как они меняются со временем — то есть как движется изображение. Для каждого промежуточного кадра она выдаёт своё представление, которое затем разворачивается обратно в картинку.

Простая линейная смесь — это «наивный» способ. Сеть движения — обученный, он учитывает, как реально движется содержимое кадров.

## 6. Управление запросами (программный интерфейс)

Приложение слушает **только локальный адрес** `127.0.0.1:17851` — запросы принимаются только с вашего же компьютера, это безопасно. Любую кнопку окна можно продублировать запросом. Ниже — самые полезные; ответы приходят в формате JSON.

Все примеры используют программу `curl` — она уже есть на каждом macOS.

### 6.1. Что сейчас происходит

```bash
curl http://127.0.0.1:17851/api/status
```

Показывает, идёт ли обучение, извлечение или создание видео.

### 6.2. Текущие настройки

```bash
curl http://127.0.0.1:17851/api/params
```

Ширина/высота кадра, путь к модели, доля мощности видеокарты и т.д.

### 6.3. Поменять настройки

```bash
curl -X POST http://127.0.0.1:17851/api/set \
  -H 'Content-Type: application/json' \
  -d '{"width":"854","height":"480","modelWidth":2,"latentChannels":32,
        "convPath":"~/YumeLayers/checkpoints/conv480.safetensors",
        "gpuPowerPercent":"45"}'
```

Ответ сообщает, какие настройки приняты, а какие не распознаны.

### 6.4. Извлечь кадры из видео

```bash
curl -X POST http://127.0.0.1:17851/api/extract \
  -H 'Content-Type: application/json' \
  -d '{"paths":["/Путь/к/видео.mp4"],"maxFrames":256}'
```

### 6.5. Список извлечённых кадров

```bash
curl http://127.0.0.1:17851/api/frames
```

### 6.6. Прочитать, какие кадры назначены начальным (A) и конечным (B)

```bash
curl http://127.0.0.1:17851/api/references
```

### 6.7. Установить начальный и конечный кадр

```bash
curl -X POST http://127.0.0.1:17851/api/references \
  -H 'Content-Type: application/json' \
  -d '{"imageA":"/tmp/yume_frames/frame_0001.png",
        "imageB":"/tmp/yume_frames/frame_0056.png"}'
```

### 6.8. Обучить сеть движения

```bash
curl -X POST http://127.0.0.1:17851/api/train-motion \
  -H 'Content-Type: application/json' \
  -d '{"steps":4000,"window":120}'
```

`steps` — число шагов обучения (больше = точнее, но дольше); `window` — длина отрезка A→B в кадрах.

### 6.9. Создать видео между A и B

```bash
curl -X POST http://127.0.0.1:17851/api/interpolate \
  -H 'Content-Type: application/json' \
  -d '{"imageA":"/tmp/yume_frames/frame_0001.png",
        "imageB":"/tmp/yume_frames/frame_0056.png",
        "seconds":2.29,"fps":24,"out":"/tmp/result.mp4"}'
```

`seconds` — длительность результата, `fps` — кадров в секунду, `out` — куда сохранить видео.

### 6.10. Журнал и итог последней интерполяции

```bash
curl "http://127.0.0.1:17851/api/log?lines=50"   # последние строки журнала
curl http://127.0.0.1:17851/api/interpolation      # итог последнего создания видео
```

### 6.11. Прочие запросы

| Запрос | Что делает |
|---|---|
| `POST /api/train` | Обучить сжиматель кадров (VAE) |
| `POST /api/pause`, `/api/resume`, `/api/stop` | Пауза / продолжение / остановка обучения |
| `POST /api/screenshot` | Сохранить текущий выбранный кадр как картинку PNG на диск |
| `GET /api/preview` | Путь к последнему превью |
| `GET /api/save-recons` | Сохранить восстановленные кадры на диск |

## 8. Результаты и честные ограничения

Качество измеряется сравнением результата с реальной последовательностью кадров того же видео:

- **PSNR** — насколько точно восстановлена картинка (в децибелах; чем больше, тем лучше: ~30 дБ — очень хорошо, ~15 дБ — заметные отличия).
- **SSIM** — структурное сходство от 0 до 1 (1 = неотличимо).

Измерение на отрезке 854×480 (A = кадр 1, B = кадр 56):

| Метрика | Простая смесь | После обучения сети движения |
|---|---|---|
| PSNR | 12.45 дБ | **14.83 дБ (+2.38)** |
| SSIM | 0.697 | 0.681 |
| Ошибка предсказания (относительно смеси) | 100% | **−93%** |

То есть сеть движения в десятки раз точнее простой смеси предсказывает, как меняются скрытые представления кадров, и это заметно улучшает итоговое видео.

**Честное ограничение:** полное совпадение с оригиналом пока не достигнуто. Остаточный разрыв связан в первую очередь с качеством первой стадии — сжатия кадров (оно ограничивает «потолок» качества реконструкции примерно 20–30 дБ). Основное направление дальнейшей работы — дообучение сжимателя на разрешении 854×480 и увеличение объёма обучающих кадров.

## 9. Структура проекта

```
YumeLayers/
├── Sources/YumeLayersCore/   # ядро: расчёты на видеокарте, обучение, модели
├── Sources/YumeLayersUI/     # окно программы (интерфейс) и локальный сервер запросов
├── Tests/YumeLayersTests/    # самопроверки
├── scripts/                  # сборка приложения, запуск тестов, проверка стиля
├── docs/                     # планы, обсуждения решений, журнал экспериментов
├── outputs/                  # результаты: видео, превью
├── screenshots/              # картинки назначенных опорных кадров (A/B)
└── checkpoints/              # настройки моделей (сами веса — в ~/YumeLayers/checkpoints)
```

**Важно про публичный репозиторий:** веса моделей (большие файлы `.safetensors`) сюда **не включены** — они пересоздаются при обучении и хранятся локально в `~/YumeLayers/checkpoints`. Исходное видео для обучения тоже не включено (файлы `.mp4` исключены из репозитория). Модель, которую требуется воспроизвести, программа обучает сама на ваших кадрах.
