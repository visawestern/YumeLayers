# YumeLayers

**YumeLayers** — экспериментальная модель генерации аниме-сцен по слоям (фон → объекты → свет) в латентном пространстве. **Чистый Swift, без PyTorch и других ML-фреймворков** — только Accelerate/vDSP + Metal (GPU, AMD Radeon Pro 5500M).

## Статус (честно)

| Компонент | Статус |
|---|---|
| Metal GPU-движок (private-буферы, тайловый matmul, свёрточные ядра) | ✅ работает: ~440 ГФЛОП/с, 61 ГБ/с |
| Позитивность всех GPU-операций vs CPU | ✅ max delta < 1e-7 |
| Численная проверка градиентов свёрточного VAE (конечные разности) | ✅ 100/100 (расхождение < 1%) |
| Обучение свёрточного VAE 480p (854×480 → латент 107×60×64) | ✅ работает, ~0.3 с/шаг |
| Тренировочный GUI (параметры в окне, выбор папки, resume, стоп, превью) | ✅ работает |
| MLP-прототипы (vae/diffusion/generate) | ✅ оставлены для сверки |
| Свёрточный VAE под 360p (640×360, старт ConvVAE.swift) | ⏳ запасной вариант |
| Текстовый conditioning | ⏳ после безусловной генерации |

## Запуск

```bash
cd /Users/apple/projects/YumeLayers
swift build -c release        # release обязателен (debug в 30–60× медленнее)

# GUI — параметры задаются в окне (рекомендуется):
open .build/release/YumeLayersUI

# CLI без флагов (дефолты: 854×480, 20 эпох, паузы для разгрузки GPU):
.build/release/YumeLayers conv
.build/release/YumeLayers check       # проверка GPU-операций
.build/release/YumeLayers convcheck   # проверка градиентов свёрток
```

## GUI (YumeLayersUI)

- **Папка с кадрами** — выбор через «Обзор…» (пусто = синтетические сцены)
- **Ширина/высота** кадра (по умолчанию 854×480)
- **Эпохи, шаги за эпоху, батч, скорость обучения, пауза** — задаются в окне
- **Продолжить с чекпоинта** — resume обучения (checkpoints/conv.json)
- **Обучить VAE** — запуск на Metal GPU (в фоне, интерфейс не блокируется)
- **Стоп** — остановка обучения
- Прогресс, лог и превью «цель | реконструкция» после каждой эпохи

## Слои и 8-канальный VAE (итерация 5)

Рендерер даёт ground-truth разметку: фон RGB | объекты RGB | маска | свет.
`ConvVAEGPU(channels: 8)` учится выдавать эти 8 каналов; потеря считается
**по слоям и по точной сборке кадра** `rgb = (фон·(1−m)+объекты·m)·свет`.
Качество (PSNR/SSIM) измеряется по собранному кадру, а не по слоям по отдельности.

```bash
swift run -c release YumeLayers layers 320 240 2026   # превью: 4 PNG
swift run -c release YumeLayers layered 60 90         # обучение, потолок GPU 90%
```

Потолок нагрузки GPU **жёстко ограничен 90%**: `safeDutyCap`,
`effectiveDutyCeiling`, `clampedGpuDuty` и `GpuDutyGuard` ставят паузу после
каждого command buffer'а, включая короткие тестовые прогоны. 100% в интерфейсе
и 99% в `gpuheat` всё равно упираются в 90%; аварийное остывание по температуре
работает в обоих режимах прогрева. Замер 856×480 / 18 с: пик **78 °C**,
29–30 Вт, шаг **142 → 144 мс без дрейфа** — защита от повторной принудительной
перезагрузки из-за перегрева (4 ноября 2026).

`layered` честно сообщает результат ворот качества. На синтетике 32×24 качество
выходит на плато: 21.40 дБ (40 шагов) → 28.80 дБ (5000 шагов) при SSIM 0.9923,
пол 30 дБ / 0.90 **не пройден**. Это ограничение ёмкости `latentC = 16`
(сжатие 32×) и фиксированного `lr`, а не нехватка шагов; подробности —
`docs/CRITIQUE.md`, итерация 5b.

Старый 3-канальный путь (`conv`, `convcheck`, `gpuheat`) и его чекпоинты
работают без изменений; 3-канальный чекпоинт у 8-канальной модели честно
отклоняется как несовместимый (код 11), обучение стартует с новых весов.

## Конвейер под ключ: реальное видео → слои → обучение (итерация 6)

Одна команда от MP4 до датасета слоёв, обучения и чекпоинта:

```bash
swift build -c release
.build/release/YumeLayers pipeline /path/to/anime.mp4 [кадры] [шаги] [ш] [в]
# пример: 16 кадров из 2-секундного отрывка, 8000 шагов, 96×72
.build/release/YumeLayers pipeline ~/Downloads/video.mp4 16 8000 96 72 2.0
```

- **Кадры** извлекаются через `AVAssetImageGenerator` из короткого непрерывного
  отрывка (по умолчанию 2 с) — не из всего ролика, иначе сцены не имеют общего фона.
- **Стабилизация камеры** (`stabilizeFrames`): панорама/зум сдвигаются перебором
  целочисленных сдвигов по SAD, кадры обрезаются до общей области (кратно 8),
  склейки сцен отбрасываются. Без этого маска различия раздувается до 80% кадра.
- **Разметка** (`LayerAnnotator`): фон = временная медиана, маска = бинарная
  разница с дилатацией, свет ≥ max(канал), объекты = кадр/свет в маске.
  Инвариант: `compose(слои) == кадр` с точностью ~3e-8.
- **Обучение**: `trainLayeredVAE` на датасете сцен, ёмкость латента `C=32`
  (сжатие 16×), косинусное расписание `lr`, чекпоинт safetensors.
- **Превью**: 7 PNG — оригинал, композит, фон, объекты, маска, свет, реконструкция.

Результат на реальном 30-минутном аниме (96×72, отрывок 2 с, GPU ≤90%):

| Шагов | PSNR, дБ | SSIM |
|---|---|---|
| 200 | 22.08 | 0.975 |
| 1000 | 24.14 | 0.984 |
| 3000 | 26.17 | 0.990 |
| 8000 | 27.30 | 0.992 |
| 12000 | 27.52 | 0.992 |

Качество растёт монотонно, SSIM давно выше планки 0.90; PSNR пока не дошёл до
30 дБ. Узкое место — скорость шага (~15 мс при батче 1, из них ~5 мс GPU),
а не ёмкость: на 12 000 шагов потеря вышла на плато ~0.011.

**Про батчинг — честный результат.** Мини-батч нескольких сцен в один command
buffer (опция `batchSize`) НЕ ускоряет: на Radeon Pro 5500M время масштабируется
пропорционально объёму работы (~5 мс GPU на сцену). Зато он улучшает качество
на шаг (меньше дисперсия градиентов). Замер 8000 обновлений на реальном клипе:

| batch | время | PSNR, дБ | SSIM |
|---|---|---|---|
| 1 | 2:04 | 27.30 | 0.9920 |
| 2 | 5:04 | 27.87 | 0.9926 |
| 4 | 8:24 | 28.20 | 0.9933 |

По умолчанию `batch = 1` (быстрейший прогресс по стене часов); `batch > 1` —
осознанная плата за качество на шаг.
