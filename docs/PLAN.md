# План работ — YumeLayers

Дотошный пошаговый план. Каждый шаг содержит: что делаем, где (файл/инструмент), как проверяем, критерий готовности.

---

## Фаза 0. Окружение (1 день)

| # | Шаг | Где | Проверка |
|---|---|---|---|
| 0.1 | Установить Python 3.11+ | система | `python3 --version` |
| 0.2 | Создать venv, поставить зависимости | `requirements.txt` | `python run.py` поднимает сервер |
| 0.3 | Проверить PyTorch с GPU | `torch.cuda.is_available()` | `True` (или MPS/CPU fallback) |
| 0.4 | Проверить ffmpeg | терминал | `ffmpeg -version` |

> Примечание: на Mac AMD (5500M) с большей вероятностью будет работать CPU/MPS. Обучение медленнее, но для прототипа 64–128px терпимо. Код автоматически выбирает доступное устройство.

## Фаза 1. Синтетический датасет (2–3 дня)

**Цель:** не зависеть от реального аниме на первых итерациях. Генерируем простые сцены программно.

| # | Шаг | Где | Критерий готовности |
|---|---|---|---|
| 1.1 | Генератор «сцен»: фон (градиент/текстура) + геометрические фигуры + направление света | `src/dataset.py` (`gen_synthetic`) | 1000+ изображений 192×192 |
| 1.2 | Разделение на слои: фон-картинка, маска объектов, сеть теней | тот же модуль | три тензора на сцену |
| 1.3 | Сохранение в `.npz`/`.pt` (input + target слои) | `data/synthetic/` | файлы открываются |
| 1.4 | Визуальная проверка 10 случайных сцен | скрипт `inspect_synthetic` | глазами видно: фон/объект/свет |

## Фаза 2. Мини-VAE (3–5 дней)

## Фаза 4. Диффузионная модель слоёв (5–10 дней)

| # | Шаг | Где | Критерий |
|---|---|---|---|
| 4.1 | Мини-DiT (patch-based transformer) для латентного 24×24 | `src/diffusion.py` | forward проходит, shape верные |
| 4.2 | Три головки выхода: фон, объекты, свет | `src/diffusion.py` | три тензора 8×24×24 |
| 4.3 | Сборщик: сумма слоёв + мягкие веса | `src/diffusion.py` | выход 8×24×24 |

## Итоговая веха

«Демо-пайплайн 360p»: аниме-видео → кадры → VAE-латент → дообученная YumeLayers → по текстовому промпту генерируется новый кадр в том же стиле.

## Открытые вопросы (фиксируются в кодексе)

- Согласование слоёв: финальный сборщик может требовать дообучения на реальных данных (тени тяжелее всего).
- Текстовый энкодер: CLIP требует интернета для скачивания весов; офлайн-мини-энкодер — запасной план.
- Аппаратные ограничения 5500M: длительность обучения в 2–4 раза выше, чем на CUDA.
