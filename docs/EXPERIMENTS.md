# YumeLayers — протокол экспериментов (Этап 0: диагностика)

> Дата: 2026-11-09. Железо: MacBook Pro 16" (2019), i9, 32 ГБ RAM,
> AMD Radeon Pro 5500M 8 ГБ VRAM, macOS 26.7.1.
> Методика: минимальный TDD-цикл, продуктовый путь (forward → vaeLoss/backward
> → applyAdam, детерминированный z), 16 синтетических кадров 128×72 (одна
> «сцена», разные seed).

## Критический вывод: формат кадра HWC vs CHW

- Модель `ConvVAEGPU` ожидает вход **CHW** (3 канала, затем h·w элементов).
- Продуктовый `gatherBatch` конвертирует `hwcToChw(source.sequentialSample())`.
- Первая версия диагностического теста подавала HWC напрямую → заниженный
  PSNR (~24.8 дБ даже при overfit). После исправления формата результат сразу
  вырос до ~31.9 дБ. **Потолок ~23.8 дБ на реальных данных НЕ связан с этим
  багом** — пайплайн использует правильный формат.

## 0.3 Градиенты
- Численная проверка градиентов (finite differences) — существующий
  `testVAEGradients` зелёный (в составе сюиты).
- Сверка с `src/vae.py` (PyTorch) недоступна на этой машине: torch не установлен,
  MPS нет, официальные пакеты macOS x86_64 ограничены ~2.2.x. Пропущено как
  необязательное (эталон недоступен).

## 0.4 Hold-out по сценам

- Обучение на сцене A (синтетика: градиент+круг+свет, 16 кадров), замер на
  сцене B (полосы).
- train PSNR = **33.18 дБ**, hold-out PSNR = **14.29 дБ** (разрыв 18.9 дБ).
- **Вывод:** модель запоминает сцену, а не генерализует. Это ожидаемо для
  малой модели на малом объёме; для G2 (перенос на реальные данные) нужны
  данные большего объёма/разнообразия и этап 1 (лоссы/патчи/ёмкость).

## Этап 1 (прогресс)
- Шаг 1: каркас лосс-переключателя — `meanL1`, `sobelLumaGradient`,
  `sobelEdgeLoss`, `vaeLossGeneric(kind:)` (+ тесты). Готово.
- Шаг 2 (под-шаг): GPU-GroupNorm — ядро `groupnorm_kernel` + `session.groupNorm`
  + CPU-эталон `groupNormCPU`; расхождение GPU vs CPU = 3.6e-7 (< 1e-3).
  Интеграция GroupNorm в `ConvVAEGPU` — следующий под-шаг.
- Шаг 2b: ResidualBlockGPU — f(x)=x+conv2(ReLU(conv1(x))), собственный backward,
  численная проверка градиентов (конечные разности, отн. ошибка ≈0%).
  Интеграция в `ConvVAEGPU` — следующий под-шаг.
- Шаг 4 (подготовка): `randomCrop` — случайный кроп HWC для обучения на патчах
  128–256px; тест проверяет размер/границы/детерминизм/валидацию.
- Шаг 3 (L1): `l1grad_kernel` + `session.encodeL1Grad` (GPU ≈ CPU, |Δ|=0),
  переключатель `lossKind` (Params/API), `dReconOverride` в trainConvVAE;
  обучение с L1 снижает loss 0.31→0.026. Sobel edge-loss — далее.
- Шаг 4б (механика): обучение на патчах (`randomCrop` 128×96 из 320×256) +
  инференс полного кадра без переобучения (полностью свёрточная сеть).
  Тест `testTrainOnPatchesFullFrame`. Реальное обучение к G2 — далее.
- Шаг 2c (подготовка): в чекпоинт добавлено поле `archVersion` (1=plain,
  2=GroupNorm/Residual), round-trip тест. Сетевая интеграция v2 — далее.
- Шаг 2c (интеграция): residual-блоки между e2-e3 и d1-d2 в
  `ConvVAEGPU(residual:)` — forward/backward/чекпоинт v2 (10 слоёв, 20 матриц);
  обучение v2 снижает loss 0.30→0.018. GroupNorm — опция.
- Этап 2 (механика): инференс полного кадра 854×480 через `reconstructPadded`
  (паддинг + обрезка). Тест `testFullFrame854Inference`.
